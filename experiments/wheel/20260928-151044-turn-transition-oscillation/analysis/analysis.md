# 2026-09-28 双轮实物测试分析（0928-01）

本轮明显抖动的幅度比 09-24 小，但仍存在持续的双髋快速往复，未达到稳定运行。明显振荡在后段右转指令发出前已经开始，处于“左转结束后再次前进”的阶段；不能将右转指令本身认定为唯一触发原因。双髋、轮速和机身角速度随后一起波动，需要继续检查策略与实物之间的动态匹配。

## 振荡和轮速跟踪

主要振荡约在 63.263–65.383 s，持续至 GetDown 前。双髋目标与实际反馈均重复出现峰谷，并非只有目标变化。

| 指标 | 右髋 | 左髋 |
|---|---:|---:|
| 目标角绝对峰值 | 0.365 rad | 0.494 rad |
| 实际反馈角绝对峰值 | 0.133 rad | 0.122 rad |
| 反馈速度绝对峰值 | 5.77 rad/s | 5.46 rad/s |
| 电机上报 effort 绝对峰值 | 16.17 Nm | 25.15 Nm |
| 调试重算 PD effort 绝对峰值 | 25.95 Nm | 37.52 Nm |

目标角不等于实际摆角，不能用 0.494 rad 表示实际髋摆幅或机身角度。后段双髋目标相关系数约 -0.889、速度约 -0.846，呈相反方向往复；这些是发布器的关节坐标，不能直接用来判定电机真实方向或独立归因为滚转。

目标峰间距中位数约 0.110 s，反馈峰间距约 0.100–0.110 s，重复波动约 9–10 Hz。数据只有约两秒且不平稳，不能据此认定系统固有共振频率。

恢复前进的最初约 0.26 秒内，右轮目标由约 3.42 升至 10.97 rad/s，而同期反馈绝对值最大约 1.00 rad/s。随后左右轮目标反复换向，目标绝对峰值分别 17.70 / 12.70 rad/s，实际轮速峰值 11.84 / 9.40 rad/s。轮端响应、地面接触动态与策略预期不一致是值得优先检查的线索，但这些差异不能单独区分摩擦、负载、延迟、轮速控制能力、标定或策略输出问题。

GetDown 前，滚转约 0.01–6.36°、俯仰约 -5.33–4.37°。关节振荡明显增长时，机身尚未出现大角度倒下。松开前进和转向指令后仍然振荡，不能靠指令归零认定策略输出已平稳。

## 与 09-24 的量级比较

两轮均取策略接管后至 GetDown 前、双髋最大绝对值。上次统计使用 header 相对时间，本轮使用 bag 相对时间；严格逐帧对齐需读取各自整数时间戳。

| 指标 | 09-24 | 09-28 |
|---|---:|---:|
| 髋目标角峰值 | 1.667 rad | 0.494 rad |
| 实际髋角峰值 | 0.281 rad | 0.133 rad |
| 髋反馈速度峰值 | 12.14 rad/s | 5.77 rad/s |
| 电机上报 effort 峰值 | 97.53 Nm | 25.15 Nm |
| 调试重算 PD effort 峰值 | 136.15 Nm | 37.52 Nm |

峰值下降与用户感受的“减轻”一致，但模型、动作缩放、操作过程以及吊绳条件都变化，不能声称某一项修改带来确定百分比的改善。现有动作缩放减半没有消除快速往复。

`*_now.effort` 来自电机板 tau_now，不是独立外部力矩传感器；`*_target.effort` 是发布器根据 RL kp/kd 和反馈重算的 PD 值，不是串口实际发送的力矩。GetDown 的实际控制增益可能不同，尤其不能把该阶段重算值作为实际控制力矩。

65.403 s 后，轮目标归零、髋目标缓慢回零，符合用户确认的 GetDown。随后俯仰最低约 -61.20°，且用户确认绳子拽住机身；这段不计入策略运行峰值，也不作为转向抖动的初始原因。

launch 日志显示 15:12:28.730 用户 Ctrl+C，两个节点随后正常退出。保存的日志没有显示异常程序崩溃；这不代替完整终端输出或总线诊断。

## 结论边界和后续方向

已支持的判断：双髋和轮速仍有持续快速波动，幅度较上次降低；本轮明显振荡先在左转后的前进阶段增长，早于后段右转；大幅俯仰属于 GetDown/绳子介入阶段。

唯一根因未确定。bag 缺少 FSM、未缩放动作、实际策略输入和推理时刻、传感器年龄、控制周期/超时计数、原始发送帧。连续的 50 Hz 调试消息不能排除内部控制、IMU 或电机通信问题；本次数据也不能证明长期静态 IMU 漂移造成振荡。

优先离线核对训练与部署的 action_scale、关节顺序/方向、PD、轮速控制形式、归一化和延迟模型，尤其区分训练本就使用 0.125，还是部署侧单独减半。需要增加记录功能时，应先单独提出并批准变更，采集 FSM、原始与缩放动作、策略输入、时间及超时统计。不要仅凭本 bag 同时修改多项 PD 或零位。

后续受控验证应分别检查站立、前进、左右转和转向后恢复前进，保持相近指令幅值与持续时间。本轮最值得复查的是转向后恢复前进的切换；硬件操作是独立任务，本次仅离线核验与归档。

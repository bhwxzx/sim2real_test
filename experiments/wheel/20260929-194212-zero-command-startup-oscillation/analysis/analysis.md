## 零指令下的动态表现

全程三轴控制输入都为零。零速度指令不要求平衡控制的每个轮目标都为零；平衡时轮子需要修正。但本段实际轮速和俯仰形成增长的往复，修正没有使机身稳定。

| 指标（GetDown 前） | 结果 |
|---|---:|
| Pitch 范围 | -15.77° 至 +14.37°，峰峰值约 30.14° |
| Roll 范围 | +3.15° 至 +4.23° |
| IMU y 角速度绝对峰值 | 2.57 rad/s |
| 右轮目标范围 | -17.12 至 +30.01 rad/s |
| 左轮目标范围 | -24.29 至 +12.79 rad/s |
| 右轮反馈范围 | -9.84 至 +17.97 rad/s |
| 左轮反馈范围 | -16.38 至 +7.51 rad/s |
| 双髋反馈速度绝对峰值 | 右 0.275、左 0.397 rad/s |

Pitch 的两个相邻负峰约相隔 0.80 秒，对应约 1.25 Hz 的往复时间尺度；只有约两秒且不平稳，不应把这个值当作稳态频率或固有共振频率。右轮目标正峰约 20.22 增至 30.01 rad/s，实际正峰约 10.80 增至 17.97 rad/s，Pitch 负峰约 -12.20 增至 -15.77°，没有表现出快速收敛。

双髋速度低于 0.4 rad/s，明显不同于 09-28 后段双髋反馈峰值 5.77 rad/s、约 0.1 秒重复波动。这里不以两个不同模型和不同工况宣称改善百分比，而是区分本次主要失稳表现。

## 跟踪滞后与初始姿态变化

四组人工配对的右轮目标/反馈极值，反馈分别晚约 120、120、140、120 ms。右轮两曲线平移 6 个调试采样点（约 120 ms）后，短窗口相关系数约 0.990；目标与反馈的 RMS 差右约 10.50、左约 8.85 rad/s。这是系统响应与异步快照共同呈现的有效相位滞后，不能将其解释为串口通信延迟或单独推理耗时。惯性、负载、速度环、摩擦、采样、推理和调试发布都可能影响该量。

接管前，固定大腿目标为 +0.733/-0.733 rad；首个策略快照改为 +0.582/-0.600 rad，跳变约 -0.151/+0.133 rad，即约 8.6/7.6°。小腿目标也改变约 0.082–0.085 rad。最初 140 ms 内实际轮速绝对值不超过约 0.033 rad/s，而大腿/小腿速度已约 1.1 rad/s。接管时腿部姿态与支撑动态变化可能构成初始扰动；该观察不能独立证明它是唯一原因。

入场 Roll/Pitch 为约 +3.41/+6.23°，仍在现有 ±8°准入范围内。准入检查只判定开始时刻条件，不保证接管后的闭环稳定；本次不支持放宽准入角度，也不应为让机器人“看起来水平”直接修改 IMU 零位。

IMU 四元数导出的 Pitch 变化率与由三轴陀螺仪及 Roll 换算的 Pitch 变化率相关系数约 0.999，RMS 差约 0.049 rad/s。说明这段快速角度变化同时伴随对应角速度，不能简单解释成只发生在姿态显示上的慢漂移。这个内部一致性检查仍不能证明绝对零位、安装方向或动态 AHRS 误差均正确。

## 退出阶段与限制

GetDown 后轮目标为零、腿部收回，后段 Pitch 降至约 -34.6°并有绳子介入。不要将全 bag 最低 Pitch 当作策略运行时峰值或抖动起因。最新 launch 日志记录用户 Ctrl+C，两个节点正常退出；AHRS 和 recorder 保存日志未显示本次异常退出或丢帧告警。这不排除未直接记录的控制/通信故障。

recorded wheel/hip effort 是电机板 tau_now；target effort 是发布器按 RL 增益重算的 PD 值，不是独立力矩测量或最终下发力矩。GetDown 实际增益不同，不能跨状态直接解释重算值。

bag 未录制机身实际线速度、轮位置、FSM、实际推理输入/原始动作、每次状态年龄、控制周期和原始总线帧。不能仅凭轮速积分准确报告机身前后位移，也不能从 50 Hz 发布连续性排除 200 Hz 控制内部超时。两轮有不同人工干预与起始 Pitch，不能给出严格模型性能 A/B 或唯一根因。

## 优先检查方向

1. 当前无速度估计模型与实物动态的匹配：核对训练端默认站姿、关节映射/方向、动作缩放（尤其部署双髋保留 0.125）、轮速控制形式、PD、观测比例、历史/reset 和训练时的延迟/摩擦模型。当前记录不证明这些契约正确，也不证明去掉速度估计这一个因素就是根因。
2. Wheel 接管首帧的腿部目标跳变与初始 Pitch：需要实际策略输入/原始输出及 FSM 时间来区分模型初始偏置、历史重置和接管姿态变化。不能凭调试快照近似回放就认定逐帧推理已复现。
3. 轮端响应：进一步用既有安全边界下的同步时间、实际发送目标与反馈量化响应，而不是把 120 ms 当作纯通信延迟并据此直接增大轮 kd。新增记录、参数修改和硬件测试应另行提出方案获批。

# 2026-11-11 Wheel-to-Leg 起跳抖动评估及 Leg-to-Wheel 对照

本次最主要的异常是 Wheel-to-Leg 启动后出现逐步放大的约 9–10 Hz 双髋目标、力矩反馈和实际角度振荡，随后全身运动偏离参考动作。数据支持“轮转腿策略与实机组成的闭环在起跳准备/起跳阶段失稳”；尚不足以将底层原因唯一锁定为某个 PD 参数、某个延迟值或机械共振。

用户现场确认：抖动发生在起跳阶段；操作意图是全程零运动指令；过渡运动明显崩溃后才用吊绳拉住，随后 GetDown。按这一事件顺序，吊绳是失稳后的保护干预。本次不能沿用 10 月 10 日“吊绳中途拉拽诱发异常”的归因。拉绳时刻未进入 bag，因此后半段的极端姿态、力矩和关节偏差不能全部归给自主控制。

## PD 解释与原因分层

本机器人通过位置/速度目标经关节 PD 产生力矩：

tau = Kp * (q_target - q_actual) + Kd * (dq_target - dq_actual)

目标与实际角度存在较大差值，可以是策略主动产生支撑或起跳力矩的正常手段。不能因目标差大而判为跟踪失败，也不能直接把目标压回实测角度。本次判断异常依据是目标、力矩与实测角度形成快速往复且振幅持续放大的运动，同时偏离几乎不动的髋参考轨迹。

1. **证据最强：W2L 起跳前段发生闭环振荡。** 9–10 Hz 目标及交变力矩在实际关节上产生了明显运动。优先检查轮转腿策略在真实轮式支撑、接触摩擦、执行器动态和反馈延迟条件下的闭环适应性。
2. **较可能的底层原因：W2L 学到的反馈修正在实机上过强或相位不合适。** 有限延迟、执行器带宽、摩擦/间隙、接触约束或观测差异都可能使原本用于修正姿态的动作变成反复过度修正。目前未进行训练环境与实机的单变量闭环对照，不能从 bag 区分这些候选项；机械状态变化也未由本次检查排除。
3. **PD 增益数值变化不支持作为两方向差异的直接解释。** 当前 W2L、L2W、Wheel、Leg 使用同样的策略 PD：髋/大腿/膝 90/3，踝 28/1.4，轮 0/0.5。共同 PD 不代表它对所有策略与支撑形态都稳定，但没有“本次轮转腿额外加大 Kp”的配置证据。
4. **通用切换首帧重置不是已证实的单一根因。** 两种转换使用同一运行时激活、动作历史重置和运动参考推进机制。W2L 切入时存在小幅目标跳变，可能激发扰动；其后振幅继续增长，比单次切换冲击更值得优先追查。
5. **双足接管、GetDown、保护拉绳不能解释早期振荡的起点。** 按目标特征和当前 FSM，本次在转换完成前已经进入 GetDown；按现场描述，吊绳在明显失稳后才介入。
6. **没有遥测层面的断流证据，但不能据此排除内部延迟。** 最大 bag 间隔约 20.25 ms，转换期间无相邻完全相同的汇总状态。调试 header 是发布时间，不是可信 IMU 接收时刻；不能用它排除 IMU 延迟、配对问题或控制调度抖动。

所有策略使用相同的 PD，并不意味着输出力矩相同；网络生成的目标差及其变化速度仍可完全不同。两个转换当前都为 59 维单帧、10 帧历史、按观测项拼接，动作尺度也相同。W2L 在 11 月更新过模型、历史配置和动作参考，但维度/布局是否与训练端完全一致仍需原始训练导出配置核验，不能仅凭可加载就宣称正确。

## 力矩数据的使用边界

“力矩反馈”来自电机板 motor_tor_now，经 SDK 直接写入 tau_now，再发布到 bag；不是本次额外安装的关节力矩传感器。目标 effort 则是调试发布器使用初始化的 rl_kp/rl_kd 和 q/dq 计算的 PD 估计，不能当作独立测量。本次策略段配置数值相同，因此可以比较波形；GetUp/GetDown 使用不同 fixed gains，不能直接将其目标 effort 当作该阶段真实指令力矩。

失稳后段左大腿 PD 估计峰值约 219.3 Nm、板端反馈峰值约 156.3 Nm；右踝估计约 69.1 Nm、反馈约 27.2 Nm。可作为大负载及限幅/带宽效应的检查线索，但既不能仅凭 YAML 中的 torque_limits 认定电机实际限幅，也不能据后段可能受绳力影响的峰值解释最早的髋振荡。下位机限流、实际增益、供电及温度均未记录。

- 最后一段结束至 W2L 第一条目标约 0.70 秒，x/y 始终为零。

这与“整段录制从未有任何转向输入”并不完全一致，故保留原始记录与现场描述，不擅自解释成有意操作或某个手柄故障。当前 W2L 的观测项不含速度命令，以上输入不是转换阶段持续的前进/转向命令，但之前的物理运动可以影响进入转换时的状态。切换前轮速未完全归零，应作为初始状态差异留存。

## 下一步建议（尚未实施）

优先核对训练与部署的 W2L 专属契约：模型哈希、观测历史及归一化、坐标/关节符号、默认姿态、运动参考时间、策略周期，以及执行器 PD、限流和反馈延迟设置。现有证据不支持先把所有关节 PD 一起降低或仅缩小目标误差。

随后用训练环境/仿真针对起跳前约 1.1 秒做受控对照，逐项加入实测初始状态、延迟、摩擦/间隙和执行器约束，观察是否复现 9–10 Hz 双髋振荡；据此再决定是否需要策略训练侧修正、输出平滑或控制参数调整。任何源码、脚本或控制配置修改，都应先提出具体方案并获得用户明确批准。

如果后续采集补充诊断，最有价值的是同步 FSM/推理帧号、实际下发 kp/kd、原始及处理后动作、关键观测、可信 IMU 样本年龄、控制周期时序，以及视频/足端接触和绳力事件。当前没有修改采集或控制代码，也没有启动硬件、提交或推送。
